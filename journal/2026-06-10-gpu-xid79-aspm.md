# GPU Xid 79 crashes fixed by disabling PCIe ASPM

One-line summary: the GTX 1080 Ti fell off the PCIe bus (Xid 79) twice, both
times about 13 minutes into training, and `pcie_aspm=off` fixed it; suspect
power-state flapping under the bursty RL workload.

## What happened

- Run 1 (mismatched driver userspace 535.309 vs kernel module 535.288 fixed
  by hot module reload): trained 13.2 minutes at about 5,000 SPS, then the
  kernel logged `Xid 79: GPU has fallen off the bus` and the GPU vanished
  (`nvidia-smi: Unable to determine the device handle`).
- Run 2 (clean reboot, kernel 6.17.0-29, matched 535.309 modules): identical
  failure 12.8 minutes in. So the driver mismatch was not the cause.
- Both times the training process left an unkillable spinning thread pinning
  `nvidia_uvm`, so module reload and PCI rescan were impossible; only a
  reboot recovers.

## Diagnosis

The RL workload keeps the GPU only about 15 percent busy (Atari stepping is
CPU-bound), so the card bounces between PCIe power states thousands of times
per minute. With the firmware ASPM policy at `default`, that power-state
flapping is a known Xid 79 trigger. The same card had run steady inference
workloads for 16 days without issue; only this bursty pattern killed it.

## Fix

- `pcie_aspm=off` added to `GRUB_CMDLINE_LINUX_DEFAULT`, plus
  `nvidia-smi -pm 1` (persistence mode) after boot.
- Verified: training attempt 3 passed the 20-minute mark with no Xid while
  both prior attempts died at about 13 minutes.

## Lesson

If long training runs on this box ever hang with a stale log, check
`sudo dmesg | grep -i xid` FIRST, before suspecting the code. And for any
future host: low-utilization GPU workloads are the ones that trip ASPM bugs.
